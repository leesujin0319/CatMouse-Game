# CatMouse 게임 월드·에셋 사이즈 기준 v0.1

## 1. 문서 목적과 우선순위

이 문서는 맵, 카메라, 캐릭터, 적, 투사체, 드롭 아이템의 크기를 같은 기준으로 제작하기 위한 팀 공용 규격입니다.

- 기준 신: `Assets/_Project/Scenes/Development/Dev_PantryBackground.unity`
- 기준일: 2026-07-28
- 길이 단위: Unity 월드 유닛(`u`)
- 현재 단계: 프로토타입 기준
- 이 문서의 월드 유닛 기준은 `prototype-layout-pixel-spec-v0.1.md`의 초기 픽셀 시안보다 우선합니다.

소스 이미지의 픽셀 수나 PPU가 달라도 게임 안에서 보이는 최종 월드 크기가 이 문서와 같아야 합니다.

## 2. 공통 척도

| 항목 | 기준값 | 비고 |
| --- | ---: | --- |
| 플레이어 표시 높이 | `1u` | 모든 크기를 비교하는 기본 척도 |
| 기준 화면비 | `16:9` | PC WebGL 및 가로형 모바일 기준 |
| UI 기준 해상도 | `1920 × 1080` | Canvas Scaler 기준이며 월드 스프라이트 해상도와 별개 |
| Orthographic Size | `4` | 화면에 보이는 세로 월드 범위는 `8u` |
| 16:9 화면의 가로 월드 범위 | 약 `14.22u` | `8 × 16 ÷ 9` |
| 1080p에서의 표시 환산 | 약 `135px/u` | 화면상 예상값이며 Sprite PPU 기준이 아님 |
| 거리 표시 환산 | `1u = 10m` | 현재 테스트 러너의 임시 거리 규칙 |

카메라의 Orthographic Size가 바뀌면 화면 세로 범위는 `Orthographic Size × 2`가 됩니다. 화면 가로 범위는 화면비에 따라 달라지므로, 맵과 전투 판정은 픽셀이 아니라 월드 유닛으로 설정합니다.

## 3. 세로 맵 레이아웃

`PantryVerticalLayout`의 현재 기준값은 다음과 같습니다.

| 영역 | 중심 Y | 높이 | 실제 Y 범위 | 역할 |
| --- | ---: | ---: | ---: | --- |
| 원경 벽 | `4.92` | `3u` | `3.42 ~ 6.42` | 바닥 위에 이어지는 식료품 저장실 벽 |
| 이동 바닥 | `0` | `7u` | `-3.5 ~ 3.5` | 플레이어와 적이 이동하는 공간 |
| 하단 근경 | `-3.25` | `0.5u` | `-3.5 ~ -3.0` | 바닥 하단을 덮는 비충돌 오버레이 |

배치 계산식은 다음과 같습니다.

```text
바닥 상단 = 바닥 중심 Y + 바닥 높이 ÷ 2
바닥 하단 = 바닥 중심 Y - 바닥 높이 ÷ 2

원경 중심 Y = 바닥 상단 - 원경 겹침 + 원경 높이 ÷ 2
근경 중심 Y = 바닥 하단 + 근경 겹침 - 근경 높이 ÷ 2
```

현재 겹침 값은 다음과 같습니다.

- 원경과 바닥의 겹침: `0.08u`
- 근경과 바닥의 겹침: `0.5u`
- 근경에는 `Collider2D`를 두지 않습니다.
- 근경은 캐릭터보다 앞에 그리지만 이동 범위를 줄이지 않습니다.

## 4. 플레이어 이동과 카메라 범위

플레이어 위치는 스프라이트의 하단 중앙 피벗, 즉 발이 닿는 지점을 기준으로 합니다.

| 항목 | 기준값 | 산출 근거 |
| --- | ---: | --- |
| 플레이어 최소 Y | `-3.5` | 바닥 하단 `-3.5` + 하단 여백 `0` |
| 플레이어 최대 Y | `2.5` | 바닥 상단 `3.5` - 플레이어 높이 `1` |
| 카메라 최소 Y | `0.5` | 바닥 하단 `-3.5` + 카메라 반높이 `4` |
| 카메라 최대 Y | `1.5` | 바닥 상단 `3.5` + 상단 노출 `2` - 카메라 반높이 `4` |
| 카메라 앞쪽 오프셋 | `3u` | 러너 진행 방향의 앞쪽 공간 확보 |
| 상단 추적 여유 | `1.4u` | 플레이어가 이 거리 이상 올라갈 때 카메라가 추적 |
| 하단 추적 여유 | `1.8u` | 플레이어가 이 거리 이상 내려갈 때 카메라가 추적 |

카메라가 가장 아래에 있을 때 화면 하단은 `-3.5`이므로 바닥 아래가 노출되지 않습니다. 가장 위에 있을 때 화면 상단은 `5.5`이며, 원경 벽은 `6.42`까지 이어져 배경 밖이 노출되지 않습니다.

## 5. 수평 무한 타일 기준

| 항목 | 기준값 |
| --- | ---: |
| 레이어별 타일 월드 너비 | `16u` |
| 타일 사이 겹침 | `0.08u` |
| 타일 배치 간격 | `15.92u` |
| 기준 화면 가로 범위 | 약 `14.22u` |
| 각 레이어의 이동 배율 | `1` |

- 원경, 바닥, 근경은 각각 독립된 수평 심리스 타일이어야 합니다.
- 한 타일의 너비가 기준 화면보다 넓어야 하며, 현재 `16u` 타일은 16:9 화면을 덮습니다.
- 좌우 끝의 색, 선, 바닥 결, 구조물 높이가 이어져야 합니다. 단순한 좌우 대칭은 심리스 타일로 보지 않습니다.
- 실내 식료품 저장실은 하나의 공간이므로 원경, 바닥, 근경의 기본 이동 배율은 모두 `1`로 유지합니다.
- 소품은 타일 이미지에 빽빽하게 고정하지 않습니다. 반복이 눈에 띄는 소품은 별도 오브젝트 풀에서 드물게 배치합니다.

세부 제작 규칙은 `docs/asset-production/endless-background-asset-rules.md`를 함께 따릅니다.

## 6. 캐릭터와 전투 오브젝트 크기

### 캐릭터

| 대상 | 표시 높이 | 피벗 | 비고 |
| --- | ---: | --- | --- |
| 플레이어 | `1u` | 하단 중앙 | 프로젝트 전체의 기본 척도 |
| 일반 적 | `1u` | 하단 중앙 | 기본 고양이 |
| 신속 적 | `0.85u` | 하단 중앙 | 작은 실루엣 |
| 탱크 적 | `1.25u` | 하단 중앙 | 큰 실루엣 |

- 폭은 원본 스프라이트의 종횡비를 유지합니다.
- 캐릭터 높이는 투명 여백을 제외한 실제 스프라이트 메시 높이를 기준으로 맞춥니다.
- 캐릭터 종류별 크기는 `EnemyArchetypeDefinition`의 `Visual Scale`을 목표 높이로 사용합니다.
- 새 적을 추가할 때는 특별한 기획 의도가 없다면 `0.8u ~ 1.4u` 안에서 시작합니다. 이 범위를 벗어나면 카메라 가독성과 이동 범위를 다시 검토합니다.

### 투사체와 치즈

| 대상 | 표시 크기 | 판정 기준 | 비고 |
| --- | ---: | ---: | --- |
| 테스트 도토리 | 약 `0.5u × 0.42u` | 반경 `0.35u` | 플레이어 앞쪽으로 직선 발사 |
| 테스트 치즈 | `0.5u × 0.5u` | 자체 반경 `0.22u` | 적 피격 방향의 반대로 산개 |
| 치즈 획득 범위 | - | 반경 `0.6u` | 플레이어 기준 |

현재 공격 발사 원점은 플레이어 하단 피벗에서 `(0.55u, 0.5u)` 떨어진 위치입니다. 플레이어 스프라이트가 변경되면 손 또는 무기 위치에 맞추되, 공격 판정 크기를 스프라이트 크기에 임의로 종속시키지 않습니다.

## 7. 적 생성 영역

| 항목 | 기준값 | 비고 |
| --- | ---: | --- |
| 최소 생성 Y | `-3.1` | 바닥 하단에서 `0.4u` 여유 |
| 최대 생성 Y | `1.55` | 플레이어 최대 Y보다 아래에서 생성 |
| 화면 오른쪽 생성 여백 | `1.25u` | 카메라 오른쪽 밖에서 생성 |
| 화면 왼쪽 제거 여백 | `1.25u` | 카메라 왼쪽 밖에서 풀로 반환 |

생성 X는 고정 좌표가 아니라 카메라 가로 반폭을 사용해 계산합니다. 화면비가 바뀌어도 적이 화면 밖에서 등장하도록 `카메라 X + 가로 반폭 + 생성 여백`을 유지합니다.

## 8. 스프라이트 임포트와 렌더링

### 크기 적용 원칙

- 게임 안의 최종 크기는 월드 유닛을 기준으로 검수합니다.
- PPU는 같은 에셋 계열 안에서 통일합니다. 서로 다른 계열의 PPU가 같을 필요는 없습니다.
- 현재 프로토타입 맵 텍스처는 `100 PPU`, 고해상도 AI 캐릭터 원본은 `1000 PPU`를 사용할 수 있습니다.
- 캐릭터는 코드 또는 프리팹에서 목표 표시 높이로 정규화하므로, PPU를 맞추기 위해 원본 이미지를 불필요하게 리사이즈하지 않습니다.
- 크기 보정을 위해 개별 오브젝트의 Transform Scale을 임의로 누적하지 않습니다. 레이아웃 컴포넌트나 적 정의 데이터의 목표값을 수정합니다.
- 캐릭터와 적은 하단 중앙 피벗을 사용합니다. 가운데 피벗은 투사체와 치즈처럼 바닥 접점이 없는 오브젝트에만 사용합니다.

### Sorting Layer 순서

뒤에서 앞으로 다음 순서를 유지합니다.

1. `FarBackground`
2. `GameplayFloor`
3. `Characters`
4. `Foreground`

같은 Sorting Layer 안에서만 Sorting Order를 세부 조정합니다. 레이어 관계를 뒤집기 위해 큰 양수·음수 Order를 사용하는 방식은 피합니다.

## 9. 크기 변경 절차

바닥이나 카메라 크기를 조정할 때는 다음 순서를 지킵니다.

1. `PantryVerticalLayout`에서 `Floor Height`와 `Floor Center Y`를 조정합니다.
2. 원경과 근경의 높이·겹침 값을 조정하고 화면 밖 노출이 없는지 확인합니다.
3. `RunVerticalBounds`의 상·하단 여백으로 플레이어 발 위치 범위를 확인합니다.
4. 카메라 Orthographic Size를 조정한 뒤 카메라 최소·최대 Y를 다시 계산합니다.
5. 적 생성 Y 범위가 플레이어 이동 범위 안에 있는지 확인합니다.
6. 16:9 Game View에서 위·아래 끝 이동, 타일 경계 통과, 적 생성과 제거를 플레이 테스트합니다.

성공 기준은 다음과 같습니다.

- 플레이어의 발이 이동 바닥 밖으로 나가지 않습니다.
- 플레이어가 최대 높이에 있어도 머리가 바닥 상단 경계를 넘지 않습니다.
- 카메라가 위·아래 한계에 도달해도 레이어 밖이나 카메라 배경색이 보이지 않습니다.
- 타일 경계 통과 시 좌우 이음새와 순간적인 빈 공간이 보이지 않습니다.
- 근경은 캐릭터 앞에 보이지만 이동과 치즈 획득을 막지 않습니다.

## 10. 현재 통합 시 확인 사항

`Dev_PantryBackground`는 Orthographic Size `4`를 사용하는 현재 맵 크기 기준 신입니다. `PlayerScene`은 아직 Orthographic Size `5`를 사용하므로 두 신을 통합할 때 `4`로 맞추거나, 카메라 변경에 맞춰 이 문서의 모든 세로 범위를 다시 계산해야 합니다. 별도 결정 전까지 `PlayerScene`의 값은 새로운 공통 기준으로 사용하지 않습니다.
