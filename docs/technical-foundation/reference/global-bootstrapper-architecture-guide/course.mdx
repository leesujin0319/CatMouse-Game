## [기술 기획안] 전역 부트스트래퍼 (GlobalBootstrapper)

> 최종 수정일: 2026-04-27
> 문서 상태: `Reviewable`

---

## 1. 개요 및 설계 목적

`GlobalBootstrapper`는 앱이 첫 씬을 열기 전에 준비해야 하는 **전역 초기화 순서**를 통제하는 진입점입니다. 목표는 가능한 것을 전부 미리 로드하는 데 있지 않습니다. 앱 전체에서 공통으로 필요한 최소 코어를 먼저 안정적으로 올리고, 그 다음 씬 조립은 `SceneDI` 같은 씬 전용 구조에 넘길 수 있게 경계를 고정하는 데 있습니다.

이 문서는 특히 `SceneDI`, `VContainer`, `Addressables`, 기획 데이터 로딩 규칙과의 경계가 흔들리지 않도록, 전역 부트스트래퍼가 어디까지 책임지고 어디서 바통을 넘겨야 하는지 정의합니다.

**이 문서가 바로 답하는 질문**

- 첫 씬이 열리기 전에 무엇까지 준비해야 하는가
- 전역 부트스트래퍼와 씬 디렉터는 어디서 책임을 나누는가
- 어떤 데이터는 부트스트래퍼에서 준비하고, 어떤 데이터는 로딩 씬으로 넘겨야 하는가
- 에디터 단독 씬 실행이나 비정상 진입은 어디서 방어해야 하는가

---

## 2. 문제 정의

앱 시작 시점의 장애는 대개 "전역 시스템이 늦게 준비되었다"는 문제보다, **무엇을 전역에서 준비해야 하는지 기준이 없다는 문제**에서 시작됩니다. 어떤 팀은 `GameManager`, `SoundManager`, `NetworkSession`, `Localization`, `SkillData`를 모두 첫 프레임에 올리려 하고, 어떤 팀은 첫 씬 진입 뒤에 각자 필요한 시점에 가져오려 합니다. 이 기준이 없으면 초기화 순서는 매번 바뀌고, 단독 씬 실행, 첫 로딩 화면, 네트워크 실패, Additive 씬 조합에서 같은 문제가 반복됩니다.

더 큰 문제는 전역 부트스트래퍼가 씬 조립 책임까지 흡수하기 시작할 때입니다. 전투에 필요한 마스터 데이터, 대용량 번들, 진행률 UI가 필요한 네트워크 동기화까지 모두 부트스트래퍼에 넣으면, 유저 입장에서는 앱이 멈춘 것처럼 보이고 개발자 입장에서는 어느 단계에서 실패했는지 추적하기 어려워집니다.

따라서 `GlobalBootstrapper`의 핵심 문제는 "무엇을 빨리 올릴 것인가"가 아니라, **앱 전역 최소 코어와 씬 전용 조립을 어떻게 분리할 것인가**를 명확히 정하는 데 있습니다.

---

## 3. 설계 목표

- 앱 전체에서 공통으로 필요한 최소 코어를 첫 씬 전 안정적으로 준비한다.
- 전역 시스템 생성과 씬 전용 조립 책임을 분리한다.
- 첫 프레임에 진행률 UI가 없는 환경에서 처리 가능한 작업만 부트스트래퍼에 남긴다.
- 로딩 UI가 필요한 무거운 에셋, 네트워크, 기획 데이터는 씬 디렉터로 넘긴다.
- 단독 씬 실행, 에디터 테스트, 비정상 진입 시 전역 컨텍스트 누락을 조기에 감지한다.
- 이후 `SceneDI`, `VContainer`, `Addressables` 문서와 충돌하지 않는 초기화 기준을 만든다.

---

## 4. 범위와 비범위

### In Scope

- 앱 시작 직후의 전역 초기화 진입점
- 전역 코어 시스템의 생성 순서
- 첫 씬 진입 전에 필요한 최소 설정과 서비스 준비
- 에디터 단독 씬 실행 감지와 전역 목업 환경 보강
- 씬 디렉터로 넘겨야 하는 책임의 경계 정의

### Out of Scope

- 씬 내부 액터 주입과 활성화 순서
- 로딩 UI 단계 설계
- 대용량 번들 다운로드와 진행률 처리
- 씬 특화 기획 데이터 파싱과 조립
- 런타임 중 동적 객체 주입과 컨테이너 해석 상세 구현

`GlobalBootstrapper`는 앱 전체에서 항상 살아 있어야 하는 코어를 준비하지만, 씬을 실제로 조립하지는 않습니다. 씬 내부 데이터 준비, 액터 활성화, 로딩 UI, 서브 매니저 위임은 `SceneDI`의 범위입니다.

---

## 5. 핵심 구조와 책임

### 5.1 책임 맵

- `GlobalBootstrapper`: 앱 시작 직후 전역 최소 코어를 준비한다.
- `ProjectLifetimeScope`: 앱 전역 서비스의 수명주기를 소유한다.
- `SceneDI`: 씬 진입 이후 로딩, 조립, 활성화, 취소를 통제한다.
- `Mock Provider`: 에디터 단독 씬 실행 시 필요한 최소 전역 상태를 보강한다.

### 5.2 무엇을 부트스트래퍼에 남길 것인가

부트스트래퍼에는 아래 기준을 만족하는 작업만 남기는 편이 안전합니다.

- 앱 전역에서 항상 필요한가
- 첫 프레임 안에 끝나거나, 최소한 UI 없이 대기해도 사용자 경험 문제가 크지 않은가
- 실패 시 씬 진입 자체를 막아야 하는가
- 씬별 차이가 아니라 앱 전체 공통 기준인가

예를 들어 전역 설정, 로컬라이제이션 기본 리소스, 공용 서비스 루트 생성, 로깅 체계 가동은 부트스트래퍼 쪽에 두기 좋습니다. 반대로 월드 번들 다운로드, 로그인 세션 동기화, 스킬 마스터 데이터 파싱, 씬 전용 풀링 예열은 로딩 UI가 있는 씬 디렉터 쪽이 더 적합합니다.

---

## 6. 초기화 흐름

부트스트래퍼는 `[RuntimeInitializeOnLoadMethod]` 같은 씬 비종속 진입점을 사용해 첫 씬 이전에 개입합니다.

1. 앱 시작 직후 전역 초기화 루틴이 호출된다.
2. 전역 로깅, 디버깅, 프로젝트 루트 컨테이너 같은 최소 코어를 준비한다.
3. 공용 설정과 앱 기초 데이터처럼 UI 없이 준비 가능한 항목을 로드한다.
4. 에디터 환경이라면 현재 진입 방식이 정상 시작 경로인지 확인한다.
5. 씬 전용 조립이 필요한 항목은 건드리지 않고 첫 씬 또는 로딩 씬으로 넘긴다.
6. 이후 씬 디렉터가 씬 전용 데이터, 네트워크, 에셋, 액터 활성화를 이어받는다.

핵심은 부트스트래퍼가 모든 것을 끝내는 구조가 아니라, **씬 디렉터가 안전하게 시작할 수 있는 최소 상태를 만드는 구조**라는 점입니다.

---

## 7. SceneDI와의 경계

`GlobalBootstrapper`와 `SceneDI`의 경계는 가장 자주 흔들리는 지점입니다. 기준은 단순합니다.

- 전역 부트스트래퍼는 앱 전체 최소 코어를 준비한다.
- SceneDI는 특정 씬을 열기 위한 조립을 수행한다.

예를 들어 `ProjectLifetimeScope`, 전역 이벤트 허브, 환경 설정, 공용 로거는 부트스트래퍼가 준비할 수 있습니다. 반면 첫 진입 씬의 월드 번들, 서버 핑, 유저 재화 동기화, 씬별 마스터 데이터, 액터 주입은 SceneDI로 넘겨야 합니다.

이 경계가 무너지면 두 가지 문제가 생깁니다. 첫째, 부트스트래퍼가 진행률 UI 없는 블랙박스가 되어 앱이 멈춘 것처럼 보입니다. 둘째, 씬 디렉터는 이미 일부 작업이 어디선가 끝났다고 가정하게 되어, 단독 씬 실행이나 재시도 경로에서 책임이 깨집니다.

---

## 8. 코어 구현 예시

Reference Example: `GlobalBootstrapper`

```csharp
using Cysharp.Threading.Tasks;
using UnityEngine;

public static class GlobalBootstrapper
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    public static async void IgniteCoreEngineAsync()
    {
#if UNITY_EDITOR
        InitializeEditorTools();
#endif

        await UniTask.WhenAll(
            InitializeProjectScopeAsync(),
            InitializeAppBaseDataAsync()
        );

#if UNITY_EDITOR
        VerifyEditorEntryPoint();
#endif
    }

    private static void InitializeEditorTools()
    {
        UnityEditor.EditorApplication.ExecuteMenuItem("Tools/Architecture/Event Logger");
    }

    private static async UniTask InitializeProjectScopeAsync()
    {
        var scopePrefab = await Resources.LoadAsync<GameObject>("Architecture/ProjectLifetimeScope");
        Object.Instantiate(scopePrefab).name = "[ProjectLifetimeScope]";
    }

    private static async UniTask InitializeAppBaseDataAsync()
    {
        await UniTask.WhenAll(
            LoadSystemSettingsAsync(),
            LoadLocalizationBaseAsync()
        );
    }

#if UNITY_EDITOR
    private static void VerifyEditorEntryPoint()
    {
        var activeScene = UnityEngine.SceneManagement.SceneManager.GetActiveScene().name;

        if (activeScene != "Scene_Title")
        {
            EditorBootstrapMockProvider.Inject();
        }
    }
#endif
}
```

이 코드의 목적은 모든 게임 콘텐츠를 미리 조립하는 것이 아닙니다. 전역 코어가 준비된 뒤 SceneDI가 이어서 씬 전용 파이프라인을 시작할 수 있게 만드는 최소 진입점입니다.

---

## 9. 실패 경로와 엣지 케이스

### 9.1 진행률 UI가 필요한 작업을 부트스트래퍼에 넣은 경우

월드 번들 다운로드, 서버 로그인, 대규모 기획 데이터 파싱을 부트스트래퍼에서 대기하면 앱이 멈춘 것처럼 보일 수 있습니다. 이 작업은 로딩 UI가 있는 씬 디렉터로 넘겨야 합니다.

### 9.2 단독 씬 실행 시 전역 컨텍스트 누락

개발자는 타이틀 씬을 거치지 않고 특정 씬만 바로 실행할 수 있습니다. 이때 전역 컨텍스트가 비어 있으면 씬 진입 직후 `NullReferenceException`이 발생합니다. 부트스트래퍼는 이 경로를 감지하고 최소 전역 상태를 보강해야 합니다.

### 9.3 전역과 씬 책임 혼합

전역 부트스트래퍼가 씬 전용 서비스까지 소유하기 시작하면, SceneDI는 형식만 남고 실제 조립 책임은 다시 전역으로 빨려 들어갑니다. 이후 씬 추가, 재시도, Additive 구성에서 경계가 무너집니다.

### 9.4 초기화 실패 후 무조건 씬 진입

전역 코어 준비가 실패했는데도 첫 씬을 그대로 열면, 장애는 더 뒤에서 더 복잡한 형태로 드러납니다. 전역 설정, 공용 루트, 필수 서비스가 준비되지 않았다면 그 실패를 부트스트래퍼 단계에서 먼저 감지해야 합니다.

---

## 10. 기획 및 운영 우려사항

전역 부트스트래퍼가 다루는 데이터는 보통 기획 데이터보다 시스템 데이터에 가깝습니다. 그래서 더더욱 "무엇을 전역에서 준비할지"를 명확히 나눠야 합니다.

최소한 아래 기준이 문서에 닫혀 있어야 합니다.

- 앱 구동에 반드시 필요한 데이터인가
- 씬별 차이가 없는 공용 데이터인가
- UI 없이 준비해도 되는가
- 실패 시 사용자에게 어떤 재진입 경로를 제공할 것인가

예를 들어 공용 폰트, 언어 키, 사운드 설정, 엔드포인트 설정은 전역 준비가 자연스럽지만, 전투 밸런스 테이블이나 월드 전용 에셋까지 전역에서 읽기 시작하면 책임이 금세 무거워집니다.

---

## 11. 디버깅 및 검증 포인트

- 첫 씬이 열리기 전에 반드시 필요한 전역 코어만 준비되는지 확인한다.
- 전역 초기화 실패가 더 뒤의 씬 장애로 숨지 않고 앞단에서 감지되는지 확인한다.
- 단독 씬 실행 시 목업 경로가 최소 전역 상태를 채우는지 확인한다.
- 씬 전용 데이터 로딩이 부트스트래퍼로 침투하지 않는지 확인한다.
- SceneDI가 이어받는 시점이 문서 기준과 일치하는지 확인한다.

---

## 12. 리뷰 체크리스트

- 전역 부트스트래퍼의 책임이 SceneDI 책임과 겹치지 않는가
- 전역 최소 코어와 씬 전용 조립이 분리되어 있는가
- 첫 프레임에 UI 없는 상태로 처리 가능한 작업만 남겼는가
- 단독 씬 실행과 비정상 진입을 감지할 수 있는가
- 전역 실패가 뒤늦은 씬 장애로 번지지 않는가

## [개발 가이드] 전역 부트스트래퍼 (GlobalBootstrapper)

> 최종 수정일: 2026-04-27
> 문서 상태: `Reviewable`

---

## 1. 개요 및 읽는 순서

`GlobalBootstrapper`는 씬 오브젝트가 아니라 앱 시작 직후 자동으로 실행되는 전역 초기화 루틴입니다. 이 가이드는 구현자가 전역 코어를 어디까지 준비하고, 어느 시점에 SceneDI로 넘겨야 하는지 코드 기준으로 설명합니다.

이 가이드를 읽을 때는 아래 순서로 보면 좋습니다.

1. 진입점 코드가 어느 시점에 실행되는지 본다.
2. 전역 루트와 앱 기초 데이터를 무엇까지 준비하는지 본다.
3. 단독 씬 실행 방어를 어디서 거는지 본다.
4. 어떤 작업을 SceneDI로 넘겨야 하는지 경계를 확인한다.

---

## 2. 이 가이드가 전제하는 계약

- 부트스트래퍼는 앱 전체 최소 코어만 준비한다.
- 씬 전용 조립은 SceneDI가 맡는다.
- 로딩 UI가 필요한 작업은 부트스트래퍼가 직접 대기하지 않는다.
- 단독 씬 실행이나 비정상 진입 경로는 전역 컨텍스트 누락 없이 방어한다.

이 계약이 무너지면 부트스트래퍼는 전역 초기화기가 아니라 씬 디렉터를 대신하는 거대한 시작 스크립트가 됩니다.

---

## 3. 런타임 진입점 구현

Reference Example: `GlobalBootstrapper`

```csharp
using Cysharp.Threading.Tasks;
using UnityEngine;

public static class GlobalBootstrapper
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    public static async void IgniteCoreEngineAsync()
    {
#if UNITY_EDITOR
        InitializeEditorTools();
#endif

        await UniTask.WhenAll(
            InitializeProjectScopeAsync(),
            InitializeAppBaseDataAsync()
        );

#if UNITY_EDITOR
        VerifyEditorEntryPoint();
#endif
    }

    private static void InitializeEditorTools()
    {
        UnityEditor.EditorApplication.ExecuteMenuItem("Tools/Architecture/Event Logger");
    }
}
```

이 진입점은 첫 씬이 렌더링되기 전에 실행됩니다. 따라서 여기서는 앱 전체에 공통인 루트만 준비하고, 사용자에게 진행률을 보여줘야 하는 작업은 넣지 않는 편이 안전합니다.

---

## 4. 전역 루트와 앱 기초 데이터 준비

### 4.1 전역 수명주기 루트 준비

Reference Example: `InitializeProjectScopeAsync`

```csharp
private static async UniTask InitializeProjectScopeAsync()
{
    var scopePrefab = await Resources.LoadAsync<GameObject>("Architecture/ProjectLifetimeScope");
    Object.Instantiate(scopePrefab).name = "[ProjectLifetimeScope]";
}
```

이 단계의 목적은 앱 전체 서비스가 의존할 수 있는 전역 루트를 올리는 것입니다. `SoundManager`, `EventBus`, 공용 설정 공급자처럼 앱 내내 살아 있어야 하는 객체는 이 루트 아래에 붙는 편이 자연스럽습니다.

### 4.2 앱 기초 데이터 준비

Reference Example: `InitializeAppBaseDataAsync`

```csharp
private static async UniTask InitializeAppBaseDataAsync()
{
    await UniTask.WhenAll(
        LoadSystemSettingsAsync(),
        LoadLocalizationBaseAsync(),
        LoadEndpointConfigurationAsync()
    );
}
```

여기서 준비하는 데이터는 앱 시작 직후 공통으로 필요한 최소 항목이어야 합니다. 공용 설정, 로컬라이제이션 기본 키, 엔드포인트 설정처럼 UI 없이 준비 가능한 항목이 대표적입니다.

반대로 아래는 SceneDI로 넘기는 편이 맞습니다.

- 월드 번들 다운로드
- 서버 로그인과 유저 세션 동기화
- 스킬, 아이템, 몬스터 스탯 같은 씬 전용 기획 데이터
- 풀링 예열과 액터 주입

---

## 5. SceneDI로 넘기는 핸드오프 기준

부트스트래퍼는 무엇이든 먼저 할 수 있는 위치에 있지만, 그래서 더 절제해야 합니다. 기준은 단순합니다.

- UI 없이 기다리게 하면 안 되는 작업은 넘긴다.
- 씬마다 달라지는 작업은 넘긴다.
- 실패 화면이나 재시도가 필요한 작업은 넘긴다.

예를 들어 `TitleSceneDirector`나 `LoadingSceneDirector`가 아래를 이어받는 구조가 자연스럽습니다.

```csharp
public class TitleSceneDirector : BaseSceneDirectorAsync
{
    protected override async UniTask InitializeSceneAsync(CancellationToken token)
    {
        await ConnectNetworkSessionAsync(token);
        await LoadTitleSceneAssetsAsync(token);
        await LoadPlayerProfileAsync(token);
    }
}
```

핵심은 전역 루트는 부트스트래퍼가, 씬 조립은 SceneDI가 맡는 구조를 유지하는 것입니다.

---

## 6. 에디터 단독 씬 실행 방어

실무에서는 타이틀 씬을 거치지 않고 전투 씬이나 보스 씬만 바로 실행하는 경우가 많습니다. 이 경로를 공식 지원하지 않으면, 개발자마다 각 씬에 임시 더미 코드를 흩뿌리게 됩니다.

### 6.1 진입 경로 확인

Reference Example: `VerifyEditorEntryPoint`

```csharp
#if UNITY_EDITOR
private static void VerifyEditorEntryPoint()
{
    var activeScene = UnityEngine.SceneManagement.SceneManager.GetActiveScene().name;

    if (activeScene != "Scene_Title")
    {
        EditorBootstrapMockProvider.Inject();
    }
}
#endif
```

이 코드는 씬 이름 하나만 비교하는 예시이지만, 실제 프로젝트에서는 빌드 엔트리 씬 목록, 개발용 진입 규칙, 테스트용 플래그를 함께 보게 될 수 있습니다.

### 6.2 목업 전역 상태 주입

Reference Example: `EditorBootstrapMockProvider`

```csharp
#if UNITY_EDITOR
using UnityEngine;

public static class EditorBootstrapMockProvider
{
    public static void Inject()
    {
        if (GameManager.Instance != null && NetworkSession.Current != null)
        {
            return;
        }

        var root = new GameObject("[EditorBootstrapMock]");
        root.AddComponent<GameManager>();
        NetworkSession.InstallMock();
    }
}
#endif
```

중요한 점은 부트스트래퍼가 씬 내부 액터까지 직접 조립하는 것이 아니라, SceneDI가 시작될 수 있을 만큼의 **전역 최소 상태**만 채운다는 점입니다.

## 7. 자주 하는 실수

### 실수 1. 부트스트래퍼에서 로그인과 대용량 로딩까지 모두 끝내려는 것

진행률 UI 없는 상태에서 오래 기다리게 만들면 앱이 멈춘 것처럼 보일 수 있습니다. 이런 작업은 SceneDI로 넘겨야 합니다.

### 실수 2. 씬 전용 기획 데이터를 전역에서 미리 읽는 것

특정 씬에서만 쓰는 데이터까지 전역에서 읽으면 부트스트래퍼가 무거워지고, 씬별 책임이 흐려집니다.

### 실수 3. 단독 씬 실행 방어를 각 씬에 따로 두는 것

이 방식은 데이터 구조가 바뀔 때 수정 지점을 늘립니다. 전역 목업 규약은 가능한 한 중앙화하는 편이 좋습니다.

### 실수 4. 전역 초기화 실패를 무시하고 첫 씬을 여는 것

실패를 앞단에서 감지하지 않으면, 장애는 나중에 더 복잡한 형태로 드러납니다.

---

## 8. 디버깅 포인트

- 첫 씬 이전에 실제로 어떤 작업이 실행되는지 로그 순서를 확인한다.
- 부트스트래퍼가 씬 전용 로딩을 침범하고 있지 않은지 확인한다.
- 단독 씬 실행 시 전역 목업이 한 번만 주입되는지 확인한다.
- 전역 실패가 씬 장애로 숨어들지 않고 앞단에서 드러나는지 확인한다.
- SceneDI가 이어받는 시점에 필요한 전역 코어가 모두 준비되어 있는지 확인한다.
