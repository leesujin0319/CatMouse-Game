# 레퍼런스 구조 분석: LAB Escape!

## 목적과 경계

이 문서는 `LAB Escape!` 추출본에서 확인한 **일반적인 게임 시스템 구조와 제작 범위**를 기록한다. 원본의 코드, 텍스처, 사운드, 프리팹, UI, 고유 명칭, 수치, 로직을 우리 프로젝트로 복사하거나 재사용하지 않는다.

활용 가능한 결과는 다음 세 가지뿐이다.

1. 자동 전진 러너에 필요한 시스템의 종류
2. 사전 과제 MVP와 상용 규모의 범위 차이
3. 우리 게임에서 반드시 다르게 설계할 지점

## 추출본에서 확인한 범위

추출본은 Unity 프로젝트 구조를 갖고 있으며, 단일 메인 씬을 중심으로 다수의 프리팹·스프라이트·오디오·스크립트를 연결한 상용 게임 규모다.

| 관찰 | 기획·기술상 의미 |
| --- | --- |
| 메인 런타임 씬 1개 | 사전 과제도 단일 씬에서 타이틀, 인게임, 결과 패널을 상태 전환으로 처리할 수 있다. |
| 프리팹 약 80개 | 상용 버전에는 적, 아이템, UI, 이펙트, 지형 변형이 넓게 분화되어 있다. MVP에서 같은 양을 목표로 하지 않는다. |
| 2D 텍스처 약 150개와 오디오 약 40개 | 아트·사운드의 양이 플레이 감각을 강화하지만, 제출작은 핵심 피드백용 최소 세트부터 제작한다. |
| 게임플레이 스크립트 약 80개 | 자동 전진 게임도 런타임, 전투, 생성, 경제, 저장, UI가 분리되어야 유지보수가 가능하다. |

## 일반화된 시스템 지도

추출본의 파일 구조에서 다음과 같은 시스템 계층을 확인할 수 있다. 아래는 우리 프로젝트에서 새로 설계할 계층이며, 원본의 클래스·필드·알고리즘을 사용하지 않는다.

```text
GameSession
 ├─ RunState: 시작 / 진행 / 레벨업 선택 / 결과
 ├─ PlayerVerticalMovement: 자유로운 상하 이동, 피해, 무적
 ├─ AutoCombat: 가장 가까운 적 탐색, 도토리 발사
 ├─ EncounterDirector: 적·치즈·장애물 조우 카드 선택
 ├─ ObjectPool: 적, 도토리, 치즈, 이펙트 재사용
 ├─ ScrollWorld: 반복 배경·지형 세그먼트 이동
 ├─ Progression: 경험치, 능력 선택, 치즈 진화
 ├─ HUD: 체력·거리·경험치·쿨타임
 └─ ResultRecorder: 거리·처치·치즈·레벨 기록
```

### 구조에서 얻을 교훈

- **오브젝트 풀링은 초기에 넣는다.** WebGL에서 투사체·치즈·적을 반복 생성하면 GC 스파이크가 체감 조작감을 망칠 수 있다.
- **반복 지형과 조우 생성을 분리한다.** 배경을 무한히 보이게 만드는 일과 전투 난이도를 만드는 일은 다른 책임이다.
- **한 판 성장과 영구 성장을 분리한다.** 사전 과제 MVP는 한 판 성장만 우선 구현하고, 영구 성장은 인터페이스 자리만 남긴다.
- **UI 상태 전환을 명확히 한다.** 레벨업에서 시간을 멈추고, 선택 뒤 안전하게 재개하는 흐름은 핵심 검증 항목이다.

## 우리 게임에 적용할 최소 구조

| 시스템 | MVP 책임 | 제외 범위 |
| --- | --- | --- |
| GameSession | 타이틀, 시작, 일시정지, 결과 | 계정, 광고, 결제 |
| ScrollWorld | 식료품 저장실 타일 3종의 반복 | 다중 맵·복잡한 전환 |
| EncounterDirector | 거리별 적·치즈·경고 패턴 선택 | 무제한 랜덤 콘텐츠 |
| ObjectPool | 고양이 4종, 도토리, 치즈, 이펙트 | 모든 오브젝트의 범용화 |
| Progression | 경험치·레벨업·능력 8종·진화 2단계 | 영구 성장·상점·수집 |
| HUD | 체력, 거리, 경험치, 액티브 쿨타임 | 광고·상점·재화 복수 표시 |

| 항목 | 사용하지 않는 방향 | 쥐생역전 방향 |
| --- | --- | --- |
| 배경·서사 | 연구소 탈출·실험체 표현 | 식료품 저장실과 치즈 회수전 |
| 플레이 공간 | 전진 중 자유로운 상하 이동 | 화면 안 세로 동선 판단 |
| 성장 표현 | 원본의 변이·카드 표현 | 치즈 진화와 도토리 장비 변화 |
| 적 상호작용 | 원본 적·패턴·이름 | 고양이의 세로 추적 돌진·투사체·위험 구역 점령 |
| 능력 중첩 | 원본의 중첩 수·효과 재현 | 최대 2회, 독자 효과와 수치 |
| 메타 시스템 | 원본 상점·상자·광고·결제 | 사전 과제에서는 제거 |
| 아트·사운드 | 추출 에셋 사용·변형 | 새로 제작하거나 라이선스가 명확한 에셋 |

## 기술 파운데이션으로 이어질 결정

1. 프로젝트 코드는 `GameSession`, `PlayerVerticalMovement`, `EncounterDirector`처럼 우리 용어로 새로 구성한다.
2. 고양이, 도토리, 치즈, 배경 타일은 모두 새 프리팹과 새 GUID로 제작한다.
3. 첫 플레이 가능 빌드는 60초 동안 다음 순서를 보장한다: 튜토리얼 이동 → 자동 공격 → 치즈 획득 → 레벨업 선택 → 엘리트 경고.
4. AI 디렉터를 도입할 경우 조우 카드 ID만 선택하게 하고, 스폰 위치·피해 수치·쿨타임의 최종 검증은 Unity의 결정론적 규칙이 담당한다.
